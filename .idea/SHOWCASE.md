# Showcasing Pulse to Employers

## Best Combo
1. **Live Vercel demo** — deploy free, share URL, they use the actual product. Working app beats any resume line.
2. **Portfolio case study** — problem → decisions → tradeoffs → outcome. The CLAUDE.md + BRANDING.md + UI_DESIGN.md docs are half the case study already written.
3. **Public showcase repo** — separate sanitized public repo: polished README, tech stack, architecture diagram, screenshots, link to demo. No business docs. Enough to show depth without giving away the product.

## Optional Additions
- **Invite-only access** — add specific employers as read-only GitHub collaborators
- **Loom walkthrough** — demo the app + talk through a technical decision (e.g. dual-file RN portability pattern, hybrid logic placement). Shows communication + technical skills together.

## Case Study Outline (for portfolio site)
1. The problem — group Italy trip, everyone wants different things, no tool exists
2. The insight — MUST/WANT/MEH compatibility matrix as the core mechanic
3. Key decisions — stack (Next.js + Supabase), RN portability strategy, theming architecture
4. What I built — feature list, screenshots, live demo link
5. What I learned / what's next

## Repo Strategy
- Main repo: **private** (code + all business docs)
- Showcase repo: **public** (README + screenshots + architecture only)
- Domain: check `pulse.travel` availability before committing to Pulse as final name
