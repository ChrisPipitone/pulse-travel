# Trip Flow

Covers: trip creation, invite link lifecycle, join flow, and the UI state machine on the trip page.

---

## Create → Invite → Join

```mermaid
sequenceDiagram
    participant O as Owner (browser)
    participant App as Next.js
    participant DB as Postgres

    O->>App: fill trip name, destination, dates · submit
    App->>DB: INSERT into trips (created_by = auth.uid())
    Note over DB: invite_code = substr(md5(random()), 1, 8)<br/>generated by Postgres default
    DB-->>App: trip row incl. invite_code
    App->>DB: INSERT into trip_members (trip_id, user_id = owner)
    Note over DB: enforce_trip_member_limit trigger fires<br/>checks owner tier cap → allow
    App-->>O: redirect to /trip/<id>

    O->>O: share /join?code=<invite_code>

    participant M as New Member (browser)
    M->>App: GET /join?code=italy25
    App->>DB: SELECT from trips WHERE invite_code = 'italy25'
    Note over DB: ⚠ RLS gap: trips SELECT requires membership<br/>See Known Gap below
    DB-->>App: trip row
    App-->>M: confirm screen "Join Italy 2025?"
    M->>App: confirm
    App->>DB: UPSERT into trip_members (trip_id, user_id = auth.uid())<br/>onConflict: ignore duplicates
    Note over DB: enforce_trip_member_limit trigger fires<br/>count >= tier cap → raise exception P0001
    DB-->>App: success or "Trip is full (X plan allows up to Y members)"
    App-->>M: redirect to /trip/<id>
```

## Invite Code

| Property | Value |
|---|---|
| Format | 8-char hex string (`substr(md5(random()), 1, 8)`) |
| Uniqueness | Enforced by `UNIQUE` constraint on `trips.invite_code` |
| Collision | Extremely unlikely at scale; no retry logic currently |
| Expiry | None — permanent until trip is deleted |
| Revoke | Not implemented — delete and recreate trip to invalidate |

Invite URL shape: `https://app.domain/join?code=<invite_code>`

## Duplicate Join

Re-clicking an invite link after already being a member is handled safely:

```mermaid
flowchart TD
    A["UPSERT into trip_members\nonConflict: trip_id,user_id\nignoreDuplicates: true"] --> B{row exists?}
    B -->|no| C[insert — member added]
    B -->|yes| D[no-op — member already joined]
    C --> E[trigger: count check]
    D --> F[success — no error]
    E -->|count < tier cap| G[allowed]
    E -->|count >= tier cap| H[raise exception P0001\n'Trip is full (X plan allows up to Y members)']
```

## Member Limit Enforcement

Cap is per the trip owner's tier, enforced at DB level via a `BEFORE INSERT` trigger — applies to all inserts regardless of path (RLS, service role, direct SQL).

| Tier | Cap |
|---|---|
| `free` | 5 |
| `planner` | 25 |
| `enterprise` | unlimited |

```
migrations/20260520000002_trip_member_limit.sql  — original 50-member cap
migrations/20260522000000_user_tiers.sql         — replaced with tier-aware trigger
  └── function: public.check_trip_member_limit() SECURITY DEFINER
  └── trigger:  enforce_trip_member_limit BEFORE INSERT ON trip_members FOR EACH ROW
```

Trigger looks up the trip owner's `profiles.tier`, resolves the cap, and raises `'Trip is full (X plan allows up to Y members)'` if exceeded. The service layer (`joinTrip`) catches errors starting with `'Trip is full'` and passes the message through to the UI.

**Gap before production:** trigger enforcement only. A client calling the API directly (or a compromised session) could attempt inserts that bypass UI guards. Needs server-side middleware or an RLS policy enforcing tier caps before real billing is live. See `docs/TIERS.md`.

## Trip Page Data Flow

```mermaid
flowchart TD
    subgraph mount["On mount — useTripData(tripId)"]
        F1["getTrip(tripId)"]
        F2["getMembers(tripId)"]
        F3["getActivities(tripId)"]
        F1 & F2 & F3 -->|parallel Promise.all| S["Zustand store\nsetTrip · setMembers · setActivities"]
        S --> F4["getRatings(activityIds)"]
        F4 --> SR["store: setRatings"]
    end

    subgraph rt["Supabase Realtime channel  trip-<tripId>"]
        R1["activities changed\n→ refetch activities"]
        R2["activity_ratings changed\n→ refetch activities then ratings"]
    end

    SR --> UI["Trip page renders"]
    rt -->|postgres_changes event| SR
```

Trip, members, and activities are fetched in parallel. Ratings follow because they require activity IDs. Realtime keeps all connected members' views in sync without polling.

## Trip Page Modal State Machine

```mermaid
stateDiagram-v2
    [*] --> closed
    closed --> add : "+ Add" button
    closed --> view : click activity row
    view --> edit : "Edit Activity" button (if canEdit)
    view --> closed : close / backdrop
    add --> closed : cancel or submit success
    edit --> closed : cancel or submit success
    edit --> view : (not implemented — goes to closed)
```

`ModalState` is a discriminated union in `apps/web/src/app/trip/[id]/page.tsx`:

```ts
type ModalState =
  | { mode: 'closed' }
  | { mode: 'add' }
  | { mode: 'view'; activity: Activity }
  | { mode: 'edit'; activity: Activity }
```

TypeScript narrows `modal.activity` automatically in each branch — no `activity?` nullable needed.

## Permission Model

| Action | Who can |
|---|---|
| View trip | Any member |
| Add activity | Any member |
| Edit activity | Adder of that activity OR trip owner |
| Delete activity | Adder of that activity OR trip owner |
| Rate activity | Any member (own rating only) |
| Add/delete trip events | Trip owner only |
| Remove a member | Member themselves OR trip owner |

`canEdit(activity)` in the trip page: `isOwner || activity.added_by === userId`. Enforced in both UI (hides edit/delete buttons) and RLS (`activities: update if adder or owner` policy).

## Invite Code Lookup — RLS Solution

`trips` SELECT RLS requires `is_trip_member(id)` — a non-member cannot query the table directly. Pure RLS cannot express "allow if the queried invite_code matches" because policy expressions have no access to query parameters.

**Fix (applied in `20260520000003_invite_code_lookup.sql`):** `SECURITY DEFINER` function `public.get_trip_by_invite_code(p_code text)` — same pattern as `is_trip_member`. Only returns the row matching the exact code; no other trips exposed. Callable by `authenticated` role only; revoked from `public`.

`getTripByInviteCode` in `packages/services/src/trips.ts` now calls `client.rpc('get_trip_by_invite_code', { p_code: code })` instead of a direct table query.
